1"""Export/import a heat's measured records between two cozer instances of the same event. 

2 

3A heat's record is addressed by **(class, phase, heat)** — ``record[base][kind][number][occurrence]`` — 

4independent of the Races-tab order, so the equivalent heat on another machine is found by that tuple 

5(if the schedules differ). This is app-layer I/O only: it reuses the existing record slot, the class 

6pattern, the participant list, and the journal ops (``heat`` + ``replace``). It changes **no** scoring 

7or seeding algorithm and **no** data structure. 

8 

9Rules (owner): 

10 * a heat imports only if the target has the same **(class, phase)** and an **equivalent race pattern** 

11 — otherwise it is rejected with a message (never silently add a class or a different pattern); 

12 * every boat that carries marks must already be a **participant** of that class in the target — a 

13 missing boat rejects the heat (never invent participants); 

14 * if the equivalent record already holds **measured data**, overwriting is **confirmed** first; 

15 * a missing **Races-tab** entry for the heat is added (schedule metadata only). 

16"""
